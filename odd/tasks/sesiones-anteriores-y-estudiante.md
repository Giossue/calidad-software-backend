# Sesiones anteriores, avisos al estudiante y ajustes de informes

Objective: teachers register and edit past sessions of the current PAO on class days through a calendar; students get the final result notification, see session dates and no longer see the teacher's phone in Horarios; report names fixed in data. Repos: calidad-software-backend + calidad-software-frontend, branch `main` (team pushes to main). Delivery: work-unit commits per repo, push on user request. Runners: `env -u DB_CONNECTION -u DB_HOST -u DB_PORT -u DB_DATABASE -u DB_USERNAME -u DB_PASSWORD -u DB_URL php artisan test` (SQLite), `npx vitest run`, `npx tsc --noEmit -p tsconfig.app.json`, `npm run lint`.

## Specs

- **S1 — Informes por apellidos y nombres (L1, L2).** "En los informe deben mostrarse los estudiantes por apellidos y nombres, no nombres y apellidos." Code already prints the stored `usuario.nombre` ("APELLIDOS NOMBRES") and sorts by it; the reversed rows are data entered before the two-field form. Answer: "Reviso producción (Recomendado)" → read-only check of production, show suspicious names, correct them only after the user approves, with a backup first. No code change.
- **S2 — Sesiones anteriores con calendario (L1, L2).** "Un docente debe poder acceder a sesiones anteriores para registrar asistencia, temas, actividades, metodologías. De preferencia colocar un calendario para revisar sesiones anteriores." Answer: "Solo días con clase", note: "aqui, los periodos anteriores no deben ser solo de consulta, sino que se pueden modificar: añadir temas, actividades, etc y podra modificarse durante todo el pao". Rule: the teacher can create or edit the session (attendance and topics covered) of any date from the start of the current academic period (PAO) up to today, as long as the tutoría has an active schedule (horario) on that weekday. Today no longer requires being inside the class hours. Future dates, dates outside the current period, days without class and tutorías of closed periods are rejected. The attendance page shows a month calendar marking class days and days with a registered session; choosing a day opens that session to register or edit it. Activities and methodologies belong to topics (Contenido) and stay editable there.
- **S3 — Fecha de cada sesión para el estudiante (L1).** "Para el estudiante debe salir la fecha de cada sesión para que tenga referencia de cuando fueron." Attendance already shows "Fecha". In the student Contenido view "Todas las clases", each topic shows the session(s) and date(s) when it was covered ("Sesión N · fecha").
- **S4 — Aviso de aprobado o reprobado (L1, L2).** "Mensaje del estado reprobado o aprobado cuando el docente lo define". Answer: "Notificar al estudiante (Recomendado)": when the teacher sets the final result, the student receives an in-app notification (bell) "Aprobaste la tutoría de {asignatura}" / "Reprobaste la tutoría de {asignatura}", and sees the status Aprobado/Reprobado in their tutoría. Removing the result sends nothing and hides the status.
- **S5 — Sin celular en Horarios (L1).** "El número de celular lo quitamos de la pestaña horarios del estudiante". The teacher's phone is no longer shown in the student Horarios tab nor returned in that student payload. Other screens unchanged.
